# Roadmap V2.1 — MyCatalog Premium UI

Baseado exclusivamente nos achados CONFIRMADOS (e nos PARCIALMENTE
CONFIRMADOS cuja parte confirmada é acionável) de
[`docs/V2.1-POST-V2-AUDIT.md`](./V2.1-POST-V2-AUDIT.md). Achados NÃO
PROCEDE, DECISÃO DE PRODUTO em aberto e DÍVIDA TÉCNICA de alto risco
(REWATCH-01) não viram item de implementação aqui — ficam documentados
como está na auditoria.

A estrutura sugerida no enunciado (A–E por tema) fez sentido e foi
mantida, com um ajuste: SEO/Observabilidade acabaram naturalmente juntas
sob "Confiabilidade Pública" (C), já que ambas são sobre o que o produto
expõe/reporta para fora do próprio usuário logado.

## V2.1-B — Product Architecture & Navigation

Prioridade média — não bloqueia nada, mas reduz dívida de manutenção e
inconsistência perceptível.

1. **FAV-02** — trocar o ícone `Eye` por `Heart` no item "Curtidos" do
   Nav. Correção trivial, fazer primeiro.
2. **FAV-01** — descontinuar a implementação duplicada de `/favorites`,
   redirecionando (ou reaproveitando o componente) para
   `/library?favorite=true`.
3. **LISTS-01** — padronizar `/lists` via middleware (`PRIVATE_ROUTES`),
   com exceção explícita para `/lists/[id]` (pública por design) — exige
   lógica de correspondência exata, não só adicionar a string.
4. **NAV-02** — avaliar (decisão de produto, não puramente técnica) se
   vale agrupar Stats/Ranking/Retrospectiva sob "Insights" via route
   group do Next.js. Tecnicamente não quebra nenhuma URL existente, mas
   não reduz código — é puramente uma mudança de navegação/UX.

## V2.1-C — Confiabilidade Pública (SEO + Observabilidade)

Prioridade alta para SEO-01 (bug real em produção); demais itens são
melhoria incremental.

1. **SEO-01** — **ação imediata fora de código**: auditar visualmente o
   valor de `NEXT_PUBLIC_SITE_URL` no ambiente Production da Vercel (sem
   expor o valor). Depois, endurecer `normalizeSiteUrl()` em
   `lib/site-url.ts` para nunca aceitar `localhost`/`127.0.0.1` quando
   `process.env.VERCEL_ENV === "production"`.
2. **SEO-04** — se `/discover` deve ser indexável, adicionar ao `allow`
   do `robots.ts` e criar override de metadata (hoje herda `noindex` do
   root).
3. **SEO-05** — adicionar JSON-LD `Movie`/`TVSeries` em
   `app/title/[type]/[id]/layout.tsx`, reaproveitando o fetch já
   existente ali.
4. **SEO-07** — favicon/ícones PWA reais — depende de existir um asset
   de marca (decisão de produto/design, não só engenharia).
5. **OBS-01/02** — adicionar `@vercel/analytics` +
   `@vercel/speed-insights` (menor esforço, nativos da plataforma já
   usada); avaliar Sentry (ou equivalente) para capturar o que hoje só
   vai para `console.error` em `error.tsx`/`global-error.tsx`.

## V2.1-D — Performance & Escala

Prioridade média — nenhum destes é uma emergência hoje (bibliotecas
atuais são pequenas), mas todos pioram linearmente com o crescimento de
uso real. Mesmo padrão em 3 lugares independentes, vale tratar como uma
frente única.

1. **HOME-02** — endpoints dedicados por prateleira da Home (Continuar
   assistindo, Fila, Recentes, Melhores avaliados), mesmo padrão já
   usado em Calendário/Atividade, com `LIMIT`/paginação no servidor.
2. **FORYOU-02** — paginar/limitar as queries de `library_items`/
   `user_hidden_titles` em `/api/for-you`; parar de rebuscar a
   biblioteca inteira a cada troca de filtro que não depende dela.
3. **COLLECTION-01** — `/api/library` aceitar filtro por lista de
   `tmdb_id`s (ou endpoint dedicado), em vez de buscar a biblioteca
   inteira para resolver status de até 40 filmes de uma coleção.

## V2.1-E — High-Value Features (avaliação de produto, não implementação imediata)

Da tabela de viabilidade da auditoria (§13), ordenado por
dificuldade×valor:

**Baixo esforço / valor real:**
- H. Filtro por duração na Library (dado já existe, dificuldade baixa).

**Esforço médio / alto valor:**
- A. Continue Watching baseado em progresso real de episódio (dados já
  existem em `episodes_progress`, só falta a query/UI).
- I. Filtros de progresso de série na Library.
- D. Smart Queue via Assistente IA já existente (reaproveita
  infraestrutura do Gemini já integrada).

**Esforço médio-alto / alto valor estratégico:**
- E. Wrapped compartilhável (potencial de aquisição, mas exige geração
  de imagem/OG dinâmica — trabalho novo).
- B. Streaming services preferidos (habilita C depois).
- J. Compartilhamento de Ranking (replicar padrão de visibilidade já
  usado em profile/lists).

**Alto esforço / caro de manter:**
- C. Aviso de título da fila chegando em streaming preferido (depende de
  B + job periódico recorrente, custo de API TMDB por usuário).
- G. Import Trakt (OAuth + mapeamento de dados novo).

**Já entregue, não é V2.1:**
- F. Import Letterboxd já existe em produção.

Nenhum destes é escopo de implementação imediata — ficam como backlog
avaliado para priorização de produto.
